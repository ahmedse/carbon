# ADR-0026 — Pulse 0.2 Close-Out (North Star Proven, Waves A–D Shipped)

- **Status:** Accepted
- **Date:** 2026-09-01
- **Deciders:** Master Architect
- **Area:** cross-cutting (AI engine + host + UX + governance)

## Context

Pulse 0.2 was authorized by [ADR-0024](./0024-pulse-0.2-north-star.md) with the eight-item north
star (PULSE-MASTER §6), invariants I1–I8 (PULSE-MASTER §7), and the seven anti-drift laws. This ADR
records that the program is now **complete and formally closed**: every north-star item is proven by
a terminal/telemetry artifact, the boundary contract held throughout (I1 enforced by
`verify.sh boundary`), and the working tree has been surgically committed so the Pulse deliverable is
an auditable unit — independent of the concurrently-developed Nibras/People work, which is
deliberately **not** part of this close-out.

Canonical references: [`docs/pulse/PULSE-MASTER.md`](../../docs/pulse/PULSE-MASTER.md),
[`docs/pulse/PULSE-0.2-ROADMAP.md`](../../docs/pulse/PULSE-0.2-ROADMAP.md),
[`docs/pulse/PULSE-UX.md`](../../docs/pulse/PULSE-UX.md).

**Invariants status:** I1 (no upward imports) — enforced mechanically, green. I2 (no durable state in
`engine/`) — held; all new persistence went to Redis/Postgres via Carbon stores. I3 (consent-gated
mutations) — held (RULE_21). I4 (every AI call carries Scope) — held. I5 (outcome copy only, RULE_23)
— held; D3 transparency surfaces describe outcomes with provenance, never engine internals. I6 (new
capability = tool/plugin/skill/lane, never spine edits or new Django apps) — held; D1–D4 added
peripheral modules/hooks/components only. I7 (terminal proof + regression tests) — each wave shipped
its test files (see table). I8 (stable prompt prefix) — held.

**Anti-drift laws:** L1 (no new durable state in `engine/`) ✓ · L2 (no upward imports) ✓ · L3 (no
auto-mutation) ✓ · L4 (grow periphery, freeze spine) ✓ · L5 (prove end-to-end — SSE streams, Redis
round-trips, reuse counters) ✓ · L6 (no stubs left for later — learned-trigger/drift dead paths
removed, not deferred) ✓ · L7 (telemetry or it didn't happen — every row above is a telemetry/test
artifact) ✓.

**Surgical commit record:** the close-out commit `741514a` contains **only** Pulse D1–D4 files (40
files, +3437/−94). Nibras/People files (backend `people/` app deltas, `ai/domain/people.py` +
`test_domain_people.py`, frontend `apps/people/**`, `api/people.js`, people i18n, `App.jsx`/
`ShellSidebar.jsx` people wiring, `PeoplePages.test.jsx`) remain **uncommitted and untouched** — they
are a separate workstream and excluded from this close-out by directive.

## Alternatives Considered

- **Close out with one "kitchen-sink" commit including Nibras/People.** Rejected — the user's standing
  rule is surgical staging; mixing workstreams would make the Pulse deliverable unauditable and
  would entangle two unrelated releases.
- **Defer close-out until after Nibras lands.** Rejected — the north-star artifacts, tests, and gate
  evidence are already green; holding them hostage to an unrelated workstream serves nothing and
  risks drift (L2/L7) in the interim.

## Consequences

- **Positive:** Pulse 0.2 is an auditable, reversible unit (commit `741514a` on top of `69161db`); the
  eight north-star items each have a named artifact; the boundary contract is still mechanically
  enforced; the 993/993 frontend suite and `verify.sh all` gate give a clean baseline for Pulse 0.3.
- **Negative / trade-off:** Nibras/People files are still dirty in the working tree (by design); the
  next Nibras commit must be staged separately. Nothing Pulse-related is blocked.
- **Do NOT re-try:** do not rewrite Wave A–D proofs "for the record" (telemetry-or-it-didn't-happen —
  the artifacts stand); do not fold uncommitted Nibras work into a Pulse commit; do not open Pulse 0.3
  without a separate roadmap ADR.
