# ADR-0024 — Pulse 0.2 North Star, Invariants & Anti-Drift Rails

- **Status:** Accepted
- **Date:** 2026-08-30
- **Deciders:** Master Architect
- **Area:** cross-cutting (AI engine + host + UX + governance)

## Context

Pulse (the in-hand reasoning engine at `backend/ai/engine/`) is architecturally strong but has five
proven gaps (audited 2026-08-30): a cold learning loop (G1), proactivity that never reaches the UI
(G2), ephemeral in-process state lost on restart (G3), dead/inert subsystems (G4), and no adaptive
reasoning lane (G5). The program to close them ("Pulse 0.2") will be executed **one phase at a time by
weaker worker models (DeepSeek V4-Flash, RULE_24)**. The dominant risk is not capability — it is
**drift**: a weak model thinning out a phase, faking a signal, leaving inert code, or silently coupling
the engine to Carbon's domain apps. We need the north-star, the invariants, and the enforcement
mechanism pinned so no worker (and no future architect) re-litigates or erodes them.

Canonical references: [`docs/pulse/PULSE-MASTER.md`](../../docs/pulse/PULSE-MASTER.md) (what Pulse is),
[`docs/pulse/PULSE-0.2-ROADMAP.md`](../../docs/pulse/PULSE-0.2-ROADMAP.md) (the phased plan),
[`docs/pulse/PULSE-UX.md`](../../docs/pulse/PULSE-UX.md) (how it must feel).

## Decision

1. **Pin the north-star.** "Pulse 0.2 is DONE" is defined by the eight proven outcomes in
   PULSE-MASTER §6 (proactive insights reach the user; continuity survives restart; learning is real
   and observable; no dead subsystems; adaptive reasoning; calibrated awareness; boundary contract
   holds; it feels alive). Each must ship a **runtime artifact** (delivered insight, persisted-after-
   restart focus, incremented reuse counter, removed inert path, logged escalation) — not "probably works."

2. **Pin the invariants I1–I8** (PULSE-MASTER §7) as review-blocking rails, chiefly:
   - **I1** — `engine/` imports **nothing** from Carbon domain apps (`catalog|mdm|dq|emissions|accounts|core`) — RULE_20/RULE_6.
   - **I2** — `engine/` writes **zero** durable state; persistence is Carbon-owned.
   - **I3** — every mutation is staged + user-confirmed (RULE_21).
   - **I5** — user-facing text describes outcomes, never internals (RULE_23).
   - **I6** — new capability = a plugin/tool/skill/lane, **never** an edit to the six-witness spine or a new Django app.

3. **Mechanically enforce the boundary.** Add `.ai-toolkit/scripts/audit-imports.sh` (greps `engine/`
   for absolute imports of the forbidden apps; ignores legitimate relative `..core` engine imports) and
   wire it into `verify.sh` as a `boundary` target included in `all` and `full`. I1 is now a
   deterministic gate, not a hope.

4. **Adopt the seven anti-drift laws** (PULSE-0.2-ROADMAP: no new durable state, no upward imports, no
   auto-mutation, grow-the-periphery/freeze-the-spine, prove-it-end-to-end, no-stubs-left-for-later,
   telemetry-or-it-didn't-happen) as the per-phase worker contract. Each phase also names a
   **shallow-implementation trap** — if the worker's output matches it, the phase is rejected.

5. **UX is a first-class acceptance surface.** Every user-facing phase must pass the **UX Acceptance
   Rubric** (PULSE-UX §10): the 4-beat story, the five data states (incl. *uncertain*), provenance +
   real (never UI-invented) confidence, legible consent, accessibility, theme tokens, `apiFetch`/SSE
   (no polling), zero RULE_23 leakage. Green lint/build alone does not pass a UI phase.

## Alternatives Considered

- **Rely on prose rules + reviewer diligence only.** Rejected — the whole premise is that weak workers
  drift; an un-enforced rule is the first thing to erode. The boundary needed a script.
- **Add a runtime import hook / linter plugin instead of a grep script.** Rejected for now — heavier,
  couples to a specific linter; a portable bash grep wired into the existing gate is sufficient and
  matches the toolkit's other scripts.
- **Put Pulse-specific gates into the shared `definition-of-done.md`.** Rejected — `shared/*` is
  portable across projects (TurnKey/Gigacast); Pulse specifics belong in the project's roadmap/ADR/UX
  docs and `project.config.md` RULEs, not in a cross-project contract. Keeping DoD generic avoids a
  toolkit-portability violation.

## Consequences

- **Positive:** I1 is mechanically guaranteed (`verify.sh boundary` / `all` / `full`); the north-star
  and invariants are un-ambiguous, so phase acceptance is objective; UX quality is gated, not assumed;
  the plan is drift-resistant against weaker models.
- **Negative / trade-off:** one extra check in the verify gate; workers must produce runtime artifacts
  and UX proof, which is more effort per phase than "tests pass" (this is intentional).
- **Do NOT re-try:** do not "temporarily" import a Carbon app into `engine/` to move faster (the gate
  will fail); do not fake a confidence/provenance value in the UI; do not leave an inert path "for
  later" (L6); do not add Pulse specifics to `shared/definition-of-done.md`.
