## 2. PROBLEM (why we are doing this)

Three overlapping pages confuse users today:

| Route | Component | Role today | Problem |
|---|---|---|---|
| `/catalog/schemas` | `SchemaCatalogPage.jsx` | Browse grid (read-only) | No create/edit — user thinks there's no CRUD |
| `/catalog/schema-manager` | `SchemaManagerPage.jsx` | CRUD grid (New/Edit/Delete table) | Redundant second grid, not surfaced, user never finds it |
| `/catalog/schemas/:tableId` | `SchemaDetailPage.jsx` | Detail w/ tabs | Fields are READ-ONLY; can't add/edit/delete fields or delete the table |

Additional defects:
- **Field type bug:** `SchemaDetailPage` Overview renders `field.field_type`, but the API field is `field.type`. Types show blank/undefined.
- **Right panel mismatch:** `RowDetailPage` uses `RowMetricsPanel` with 3 rich tabs (DQ Metrics / Lineage / Related). `SchemaDetailPage` has only 1 static "Summary" tab. They look inconsistent.
- **Catalog card "0 fields":** `SchemaCatalogPage` + `SchemaManagerPage` cards read `table.fields_count`, but the list serializer (`DataTableSerializer`) does NOT return that key → always shows 0.

**Success = all three user questions answered:**
1. "Where do I create/CRUD schemas?" → In the Catalog (New Table button) + inside the Detail page (fields + delete).
2. "Why is the right sidebar not like Row Detail?" → It now uses the same multi-tab metrics pattern.
3. "I expect CRUD of the schema inside the schema." → Detail page Structure tab does full field CRUD + table delete.

## 4. BACKEND READINESS (already done — DO NOT modify backend)

All endpoints live under `/carbon-api/` and are reachable (verified live). Use the existing `apiFetch`-based wrappers — never raw `fetch()`.

### Tables — `dataschema/tables/`
- List: `fetchDataSchemaTables(token, project_id=null, module_id=null)` → array.
- Create: `createDataSchemaTable(token, data, project_id, module_id)` — **`data` MUST include `module` (required FK id)** plus `title`, optional `description`.
- Update: `updateDataSchemaTable(token, id, data, project_id, module_id)` (PUT).
- Delete: `deleteDataSchemaTable(token, id, project_id, module_id)`.
- Table/field create/update/delete now **auto-write to `SchemaChangeLog`** (add/edit/delete + before/after + user). The Audit History tab shows these live.

### Fields — `dataschema/fields/`
Wrappers in `carbon-frontend/src/api/dataschema.js`:
- `fetchDataSchemaFields(token, table_id, project_id, module_id)`
- `createDataSchemaField(token, data, project_id, module_id)`
- `updateDataSchemaField(token, id, data, project_id, module_id)` (PUT)
- `deleteDataSchemaField(token, id, project_id, module_id)`
- `updateDataSchemaFieldOrder(token, tableId, fields, project_id, module_id)` — body `{data_table, fields:[{id,order}]}`

**DataField writable fields:** `data_table` (id, required), `name` (unique within table, ≤50 chars), `label`, `type`, `order`, `description`, `required` (bool), `options`, `validation`, `is_active`, `reference_table`.
**`type` enum (exact):** `string | text | number | date | boolean | select | multiselect | file | reference`.
**Rule:** for `select`/`multiselect`, `options` MUST be a non-empty list of objects each having a `value` key, e.g. `[{ "value": "a", "label": "A" }]`. Server rejects otherwise.

### Schema change log — `dataschema/schema-logs/`
- `fetchSchemaChangeLogs(token, { data_table })` (already added). **Admin/admins_group read-only** on server → non-admins get 403; handle gracefully (already handled in `AuditHistoryTab`).

### Quality (for metrics panel Quality tab)
- Catalog asset for a table: `fetchAssetProfiles(token)` → find `a.data_table === Number(tableId) && !a.data_field`. Read `quality_status` (`unknown|passing|warning|failing`) and `quality_score` (0–100 or null).
- Optional table DQ metrics: `getTableDQMetrics` exists but is buggy (double-URL) — DO NOT use it. Prefer the asset profile fields above, and (optional) `listDQRules(token,{data_table:tableId})` count.
